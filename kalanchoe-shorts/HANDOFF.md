# KALANCHOE RECORDS ショート動画 引き継ぎ

Claude のチャットで進めていた作業を Claude Code に引き継ぐための文書です。依頼者は川西さんです。

## 目的

KALANCHOE RECORDS は草野華余子さんが主宰する東方アレンジサークルです。川西さんは YouTube チャンネル @kalanchoerecords の数字を伸ばしたいと考えていて、手持ちの音源とジャケットから YouTube ショート用の縦型動画を作ることにしました。

2026年11月24日に確認した時点で、チャンネル登録者は681人、動画は11本でした。動画は各EPのトレーラーと代表曲のMVだけで、ショートは1本もありませんでした。

参考にしているのは FELT（@Felt2010）のショートです。ジャケット、波形、曲名、タイマーを並べた試聴用の形で、川西さんはまずこの形で作る方向です。デザインは FELT の模倣にせず、ジャケットの色味に合わせて組んでいます。

## 現在の状態

1本目の「パーティ・オンザ・デッドライン」は v4 まで書き出して川西さんに渡しました（2026年11月25日）。v4 への感想はまだ受け取っていません。

- v2：チャットで作った版。
- v3：文字を AXIS Std に替えた版。
- v4：サビだけの約33秒に切り直し、動きを motion-video-studio スキルの決まりごとに合わせて作り直した版。

ジャケットとロゴは川西さんの Google Drive にあり、Drive の連携で取得できます。音源の WAV は 10MB を超えるので Drive の連携では取得できず、チャットにも 20MB の zip は添付できませんでした。川西さんに zip を 10MB ずつの分割ファイル（`.zip.001` など）にしてもらい、つなげて展開しました。

この文書と一緒に次の2つを渡します。

- `make_short.py` は動画を作るスクリプトです。
- `potd.json` は「パーティ・オンザ・デッドライン」用の設定です。

音源、ジャケット、ロゴ、フォントは同梱していません。音源、ジャケット、ロゴは川西さんが持っています。フォントの入手先は「フォント」の節に書きました。

## フォルダ構成

```
kalanchoe-shorts/
  HANDOFF.md
  make_short.py
  potd.json
  fonts/   フォント4ファイルを置く
  src/     track.wav  jacket.jpg  logo_black.png を置く
  work/    中間ファイル（自動で作られる）
  out/     完成した mp4（自動で作られる）
```

`potd.json` の中のパスは、コマンドを実行するフォルダからの相対パスです。コマンドは `kalanchoe-shorts/` の中で実行します。

川西さんから受け取った素材は次の4つです。`src/` に置くときは右の名前に変えます。

| 受け取ったファイル名 | 中身 | 置く名前 |
|---|---|---|
| `noiseOK_TR001_KUSANOKAYOKO_Party_on_the_Deadline_4416_rec05_premaster01.wav` | 音源。44.1kHz、16bit、ステレオ、3分35秒 | `src/track.wav` |
| `261004_______260929_1_1.jpg` | ジャケット。2048×2048 | `src/jacket.jpg` |
| `KALANCHOE_RECORDS_logo_black.png` | ロゴの黒版。945×945、背景は透過 | `src/logo_black.png` |
| `KALANCHOE_RECORDS_logo_color.png` | ロゴのカラー版。今は使っていない | 置かなくてよい |

動画の中のロゴは、黒版の透過情報だけを使って白抜きで描いています。

## 動かし方

Python 3 と ffmpeg が必要です。Python のライブラリは numpy、opencv-python、soundfile、Pillow を使います。

Pillow は libraqm 付きでなければなりません。カナの字間を詰める `palt` の指定に libraqm を使うためです。次のコマンドが `True` を返せば使えます。

```
python3 -c "from PIL import features; print(features.check('raqm'))"
```

静止画で確かめてから全体を書き出します。

```
python3 make_short.py potd.json --frames 0,0.3,1.3,2.0,2.8,12
python3 make_short.py potd.json --render
```

`--frames` に秒を並べて指定すると、その時刻の画面が `work/t2_秒.png` に出ます。`--render` は `out/` に mp4 を書き出します。チャットの作業環境では書き出しに約15秒かかりました。

同梱の `make_short.py` と `potd.json` を新しいフォルダで実行し、川西さんに渡した v2 と同じ映像になることを確かめてあります。

## フォント

v3 から、文字はすべて AXIS Std に替えました（川西さんの依頼）。AXIS Std は商用フォントで、川西さんから受け取った OTF を使います。リポジトリには入れていないので、`fonts/` に次のファイルを置きます。

| 役割 | ファイル |
|---|---|
| 曲名、タグ | `axisstd-bold.otf` |
| 原曲名とクレジットの本文、タイマー | `axisstd-regular.otf` |
| 英字の小見出し | `axisstd-medium.otf` |

役割ごとのフォントは `make_short.py` の `FONTS` で決めています。設定ファイルに `"fonts": {"title": ["axisstd-heavy.otf", null]}` のように書くと、その曲だけ替えられます。2つ目の値は可変フォントの wght で、静的フォントでは `null` です。

文字の位置はベースラインで指定しているので、フォントを替えても v2 と同じ位置に文字が乗ります。タイマーの数字は幅をそろえて描くので、秒が変わっても横に揺れません。

v2 で使っていた Shippori Mincho B1、Zen Kaku Gothic New、Oxanium は `fetch_fonts.sh` で取得できます（SIL Open Font License）。

AXIS Std には全角チルダ（U+FF5E）があるので、原曲名「死体旅行 ～ Be of good cheer!」は v3 から全角チルダに戻しました。

## 動画の仕様

- 画面は 1080×1920 の縦型で、30fps です。
- 長さは 32.89秒で、987フレームです。
- 映像は H.264 です。libx264 の crf 16、yuv420p、bt709 で書き出しています。
- 音声は AAC 320kbps、44.1kHz、ステレオです。
- 出力先は `out/KALANCHOE_PartyOnTheDeadline_short_v4.mp4` です。
- 書き出しには約1分かかります（4コアで並列に描画）。

## 切り出し区間

川西さんの「サビの30秒だけでいい」に合わせて、v4 からサビ1回目の全体を使っています。原曲の 0:55.24 から 1:28.13 までです。

- 0:55.22〜0:55.42 はサビ前のブレイクで、ほぼ無音です。動画はこの無音から始まります。
- 0:55.44 にサビ前のピックアップがあります。
- 0:55.86 がサビ頭で、動画の 0.62秒に当たります。
- テンポは約119BPM（1拍 0.504秒）です。サビ頭から16小節（64拍）が 32.27秒で、1:28.13 で終わります。

v2 の解析では 1:12〜1:28 を「間奏のリフ」としていましたが、受け取った WAV で調べ直すと、0:55.86〜1:28 は音の広がりと音量がずっと同じ性格で、途中で区切れる様子がありませんでした。川西さんが「サビの30秒」と言ったことと合わせて、この32秒をサビ1回目と判断しています。耳では確かめていません。

1:30.3〜1:31.3 に音が薄くなるところがあり、1:34 ごろから次の A メロと見られる区間が始まります。

v2 で推定した曲の構成は次のとおりです。上のとおり、1:12〜1:28 はサビの後半と見るほうが合っているようです。

| 原曲の時刻 | 推定した内容 |
|---|---|
| 0:00〜0:08 | 静かな導入 |
| 0:08〜0:24 | イントロのリフ |
| 0:24〜0:40 | Aメロ |
| 0:40〜0:55 | Bメロ |
| 0:55.22〜0:55.42 | ブレイク。ほぼ無音 |
| 0:55.44 | サビ前のピックアップ |
| 0:55.86〜1:28.13 | サビ1回目（v2 では 1:12 以降を間奏のリフとしていた） |
| 1:28〜2:01 | Aメロ、Bメロ |
| 2:01〜2:17 | サビ2回目 |
| 2:17〜2:57 | リフのあと静かな区間 |
| 2:57〜3:13 | サビ3回目 |
| 3:13〜3:30 | アウトロのリフ。3:30.3 が最後の一発 |

## 画面の動き

時刻は動画の開始からの秒数です。v4 の動きは「上品」な性格でそろえ、次の決まりごとで組んでいます。

- イージングは3本だけ使います。画面内の移動は `cubic-bezier(0.4, 0, 0.2, 1)`、登場は `cubic-bezier(0, 0, 0.2, 1)`、退場は `cubic-bezier(0.4, 0, 1, 1)` です。
- 主動作（ロゴ、ジャケット、文字）、二次動作（ジャケットの影）、アンビエント（背景）の3層で組んでいます。
- どの要素も、1回の動きで画面の高さの1/3（640px）を超えて動かしません。v3 まではジャケットが画面の下から約1730px 動いていました。
- 要素はすべて下から上へ入ります。

| 時刻 | 動き |
|---|---|
| 0〜0.62 | 暗い背景の中で、大きなロゴがレンズのボケ（半径46px）からピントが合う。サビ頭でピントが合いきる。背景は 0.82秒かけて明るくなる |
| 0.42〜1.12 | ロゴが縮みながら上の定位置へ移動する。ジャケットより先に動いて道をあける |
| 0.62〜1.63 | サビ頭でジャケットが 600px 下から上がり始め、2拍後の 1.63秒に着地する。大きさは 96% から 100%、最初の35%の時間で不透明になる。浮いているあいだは影が遠く大きく薄く、着地すると影が締まる |
| 1.18〜 | 波形、英字の小見出しとタイマー、曲名、原曲、クレジットが、0.07秒ずつ遅れて 24px 下から上がりながら出る。ジャケットが9割ほど上がったところで始まる |
| 全編 | 背景がゆっくり5%寄りながら少し下がる。ロゴとジャケットが上がるあいだは、背景が逆に 60px 下がる |
| 0.62〜 | 背景の明るさが低音（45〜110Hz）に合わせて最大5%だけ脈打つ |
| 最後の1.2秒 | 画面全体が冒頭と同じ暗さ（45%）まで落ちる。ショートのループで冒頭へ自然につながるようにするため |

## レイアウト

座標は 1080×1920 の画面上のピクセルです。

| 要素 | 位置と大きさ |
|---|---|
| ロゴ（定位置） | 高さ128、上端 y=62、左右中央 |
| ロゴ（冒頭） | 高さ430、中心 y=764、左右中央。y=0〜1527（YouTube の文字が重ならない範囲）の中央 |
| ジャケット | 860×860、左上が x=110、y=226 |
| 波形 | 幅860、高さ80、左上が x=110、y=1118。棒は58本 |
| 文字のブロック | 左端 x=110、右端 x=930。下端はおよそ y=1524 |

文字の右端を x=930 までにしたのは、ショートの画面で右側に並ぶボタンを避けるためです。y=1527 より下は、チャンネル名やタイトルが重なる場所なので空けてあります。

色は、文字がオフホワイト（246, 243, 236）、小見出しと波形の再生済みの部分が金色（233, 210, 154）です。背景はジャケットを拡大してぼかしたものです。

## 音声の処理

元の音源は統合ラウドネスが -6.0 LUFS、トゥルーピークが -0.2 dBFS です。

v4 の区間には、AAC にするとピークが大きく跳ねるところ（原曲の 1:23.7 付近）があります。-2dB 下げただけでは書き出した動画のピークが +1.3 dBFS になったので、全体を 5dB 下げています（設定の `gain_db`）。書き出した動画は -10.6 LUFS、トゥルーピーク -2.6 dBFS です。

YouTube は再生時に大きすぎる音を約 -14 LUFS まで下げるので、ここで 5dB 下げても YouTube での聞こえ方の大きさは変わりません。

このほかの処理は、冒頭 0.05秒のフェードインと最後 2.0秒のフェードアウトだけです。冒頭はブレイクの無音から始まるので、フェードインは短くしています。

## 設定ファイルの項目

曲を増やすときは `potd.json` を複製して値を変えます。

| 項目 | 意味 |
|---|---|
| `audio`、`jacket`、`logo` | 素材のパス |
| `start` | 原曲の何秒から切り出すか |
| `duration` | 動画の長さ。秒 |
| `lead` | 動画の開始からサビ頭までの秒数。ロゴのピントがここで合い、ジャケットが上がり始める |
| `land` | ジャケットが着地する時刻。サビ頭の2拍後にしている |
| `gain_db` | 音量を下げる量。dB。省略すると -2 |
| `fade_in`、`fade_out` | 音声のフェードの秒数 |
| `outro` | 最後に画面を暗くする秒数。省略すると 1.2 |
| `eyebrow` | 英字の小見出し |
| `title` | 曲名 |
| `originals_lines` | 原曲名。配列の1要素が1行 |
| `credits` | タグと名前の組の配列 |
| `fonts` | 役割ごとのフォントの上書き。省略できる |
| `out` | 出力先 |

ロゴが上へ動き出す時刻（`lead` の0.2秒前）や、文字が出始める時刻は `lead` と `land` から決まります。

曲名は幅に収まるように、68px から自動で小さくなります。原曲名とクレジットは自動で折り返さないので、右端の x=930 を超えないように行を分けます。

小見出しの「6TH EP」は、チャンネルの動画タイトル「KALANCHOE RECORDS 6th EP「Party on the Deadline」Trailer」に合わせました。クレジットは川西さんから受け取った作詞と編曲だけを載せています。ボーカルの表記は受け取っていません。

## 川西さんからの修正依頼

v1 を渡したあとに次の4点を頼まれ、v2 で対応しました。

1. 最初にアニメーションが欲しい。ロゴが被写界深度のぼかしからピントが合っていく感じにする。
2. そこからジャケットが下からスライドしてくる。
3. フォントがAIっぽいので見た目を整える。
4. ショートで投稿するので 1080×1920 の縦型動画にする。

3 は、Noto Sans CJK と Noto Serif CJK で組んでいた文字を、「フォント」の節の3書体に替えて対応しました。曲名はカナの字間を詰め、「原曲」などは金色の文字から枠付きのタグに変えています。4 は v1 の時点で 1080×1920 でした。

v2 のあと、次の2点を頼まれました。

5. フォントが嫌。AXIS Std の OTF を受け取り、文字をすべて AXIS Std に替えた（v3）。
6. サビの30秒だけでいい。サビ1回目の全体（約33秒）に切り直した（v4）。

v4 では、川西さんが motion-video-studio スキルを呼んだので、動きもスキルの決まりごと（イージングの統一、1/3ルール、主動作・二次動作・アンビエントの3層、退場は加速）に合わせて作り直しました。

## 未確認のこと

- サビの範囲（0:55.86〜1:28.13）を川西さんが耳で確かめたかどうか。
- 音源のファイル名に「premaster」とあります。公開用の最終マスターが別にあるかを川西さんに尋ねましたが、返事はまだありません。
- 文字の大きさ。motion-video-studio スキルは横1080px で見出し84px、補足44px 以上としていますが、今は曲名が約66px、本文が27px、タグが19px です。ジャケットを 860px のまま残し、ボタンと YouTube の文字を避けると、この大きさが上限に近いです。大きくするならジャケットを小さくするか、原曲名を減らす必要があります。
